Appendix: Prompt Format Under Different Experimental Settings

This appendix documents the exact prompt structure generated by the current implementation.
The source of truth is `src/prompt_builder.py`, with the mode selection coming from `src/run.py`
and `src/run_all_permutations.py`.

1. Shared prompt skeleton

All modes share the same overall structure:

```text
You are participating in the Water Allocation Challenge programmatic game.
[context line depends on opponent_info_mode]
Analyze the available context to generate a winning bidding strategy.

Your Profile:
<JSON profile>

Current Meta-Round State:
<JSON game state>

[optional opponent source code block]

LATEST METAROUND CONTEXT (YESTERDAY):
<JSON history payload>

After brief reasoning, generate executable Python code.

CRITICAL PYTHON RULES:
1. Function MUST be exactly: def get_bid(day_context, my_status, opponents_status):
2. 'day_context' ONLY has fields: ['supply', 'day']
3. 'my_status' ONLY has fields: ['hp', 'budget', 'no_water_days']
4. 'opponents_status' is a dictionary keyed by opponent agent_id.
5. Each opponent state has: ['agent_id', 'hp', 'budget', 'no_water_days', 'alive', 'water_requirement', 'daily_salary', 'last_bid', 'last_status', 'last_hp_after', 'last_budget_after', 'trace_history'].
6. 'trace_history' is a compact list of that opponent's recent 2 day records. Each record has: ['day', 'bid', 'supply', 'hp_after', 'budget_after', 'status', 'error'].
7. Use 'last_bid', 'last_status', 'last_hp_after', and 'last_budget_after' for quick yesterday information. Use 'trace_history' only when you need the last 2 days of trend analysis.
8. Bidding is simultaneous. Current-day opponent bids are hidden.
9. CRITICAL INDEX RULE: In Python, list/array indices MUST be integers. Since day_context['supply'] is passed as a float, wrap all list indices or subscript selectors with int() when needed.
10. High-Level Game Theory Example:
<example code>
11. DO NOT use undefined variables.
12. DO NOT use markdown code fences (```).

Agent Constants:
WATER_REQ = <agent water requirement>
DAILY_SALARY = <agent daily salary>
MAX_SUPPLY = 25
MIN_SUPPLY = 15

<short reasoning instruction>
Output valid JSON only.
Output format:
{
  "reasoning": "your short game-theoretic analysis",
  "code": "def get_bid(...)"
}
```

2. Mode: full_code_access

This mode is used when `opponent_info_mode = "full_code_access"` and opponent source code is actually revealed.

Prompt behavior:

- The second line says: `You have opponent source code and last meta-round outcomes.`
- A dedicated block appears after the game state:

```text
=== CRITICAL: OPPONENT SOURCE CODE ===
Below is the exact Python code currently used by your opponents in this meta-round.
Analyze it to find their tactical flaws:
<JSON opponent code>
```

- The history block contains the current meta-round history summary, including your own summary and the opponent summaries from the last meta-round.
- The reasoning instruction says: `Keep reasoning under 60 words, focusing on how you exploit their YESTERDAY code/trace.`

Important implementation note:

- The code block above is only inserted when both `show_opponent_code` is true and `opponent_code` is non-empty.
- In normal runs this happens when `opponent_info_mode == "full_code_access"` and `config.REVEAL_OPPONENT_CODE == True`.
- If code reveal is disabled, the prompt still uses the same mode label, but the explicit opponent source code block is omitted.

Example layout:

```text
You are participating in the Water Allocation Challenge programmatic game.
You have opponent source code and last meta-round outcomes.
Analyze the available context to generate a winning bidding strategy.

Your Profile:
{...}

Current Meta-Round State:
{...}

=== CRITICAL: OPPONENT SOURCE CODE ===
Below is the exact Python code currently used by your opponents in this meta-round.
Analyze it to find their tactical flaws:
{...}

LATEST METAROUND CONTEXT (YESTERDAY):
{...}
```

3. Mode: outcome_only

This mode is used when `opponent_info_mode = "outcome_only"`.

Prompt behavior:

- The second line says: `You have last meta-round outcomes for all agents, but no opponent code.`
- The opponent source code block is not included.
- The history block includes opponent summaries from the previous meta-round, but not source code.
- The reasoning instruction says: `Keep reasoning under 60 words, focusing on outcome patterns from the last meta-round.`

Example layout:

```text
You are participating in the Water Allocation Challenge programmatic game.
You have last meta-round outcomes for all agents, but no opponent code.
Analyze the available context to generate a winning bidding strategy.

Your Profile:
{...}

Current Meta-Round State:
{...}

LATEST METAROUND CONTEXT (YESTERDAY):
{...}
```

4. Mode: no_opponent_info

This mode is used when `opponent_info_mode = "no_opponent_info"`.

Prompt behavior:

- The second line says: `No opponent info is available; only your own last meta-round outcome is provided.`
- The opponent source code block is not included.
- The history block contains only the agent's own summary if available; otherwise it may fall back to the latest available history entry.
- The reasoning instruction says: `Keep reasoning under 60 words, focusing on your own last outcome and survival.`

Example layout:

```text
You are participating in the Water Allocation Challenge programmatic game.
No opponent info is available; only your own last meta-round outcome is provided.
Analyze the available context to generate a winning bidding strategy.

Your Profile:
{...}

Current Meta-Round State:
{...}

LATEST METAROUND CONTEXT (YESTERDAY):
{...}
```

5. History payload construction

The `LATEST METAROUND CONTEXT (YESTERDAY)` block is built from a compact history payload.

- If the input history already contains `last_meta_round`, `self_summary`, or `opponent_summaries`, those fields are kept.
- If those fields are absent, the builder falls back to the latest history entry by key order.
- If that latest entry has a nested `summary` field, the `summary` object is used.
- If no usable history exists, the block becomes an empty JSON object: `{}`.

In practice, this means the appendix can describe the prompt as stable at the top level, while the history block varies according to what the previous meta-round log contains.

6. Summary table

| Mode | Opponent code block | Opponent summaries in history | Main reasoning focus |
| --- | --- | --- | --- |
| full_code_access | Yes, if reveal is enabled | Yes | Exploit yesterday's code and traces |
| outcome_only | No | Yes | Exploit yesterday's outcome patterns |
| no_opponent_info | No | No, or only self-summary | Reason from own survival history |

7. Suggested paper wording

If you want to describe the implementation in the appendix of an AAAI full paper, a concise wording is:

> The prompt template consists of four fixed sections: system introduction, agent/game state, optional opponent information, and a strict JSON response format. Depending on the experimental setting, opponent information is exposed as either source code, outcome summaries, or omitted entirely. The history block is populated from the latest meta-round record and falls back to the most recent available summary when needed.
