Alympics Future Work Handover
Date: 2026-06-18

[1] 專案目前狀態（摘要）
本專案已完成多代理 Water Allocation Challenge（WAC）實驗框架。
目前主要可穩定執行的流程為批次實驗腳本 run_all_permutations.py，並已可自動輸出每次 experiment 與整個 batch 的統計結果。


[2] 現有整體架構（簡要）
1) Strategy Generation Layer
   - 每位 agent 透過 LLM 生成 bidding strategy code。
   - 支援多後端（openai/gemini/deepseek）。

2) Simulation Layer
   - WAC 環境執行 10-day episode，更新 hp、budget、survival 狀態。
   - 可設定 opponent info 模式，控制跨 meta-round 可見資訊。

3) Experiment Orchestration Layer
   - run_all_permutations.py 進行模型排列組合與切片批次執行。
   - 每個 experiment 會呼叫 run.py 完成 meta-round 流程。

4) Logging and Aggregation Layer
   - 每個 experiment 輸出 meta_round logs、backend_config、agent_averages、inference 檔案。
   - 每個 batch 輸出 global_batch_report，做 model/agent 層級彙整。


[3] 已完成實驗（目前可引用）
1) 已完成三種 opponent info 模式的批次實驗：
   - full_code_access
   - outcome_only
   - no_opponent_info

2) 每種模式皆以 120 次獨立 experiment 為目標批次規模執行。

3) 目前主實驗比較骨架已完成，可支援後續新模組（例如 LLM judge）接入後重跑與對照。


[4] 已有初步觀察（full code access vs no opponent info）
前期數據觀察已整理於 observation.txt。
此檔案包含目前對 full_code_access 與 no_opponent_info 的初步現象摘要，供後續會議與 judge 設計時參考。


[5] 下一階段：LLM Judge（規劃中）
目前團隊正在討論 LLM judge 的具體設計，尚未定案。
本階段建議先維持下列原則：
1) 不改動既有主實驗 pipeline 的核心輸出格式。

3) judge 指標與評分 rubric 定案後，再補一輪統一重跑與報告整併。
